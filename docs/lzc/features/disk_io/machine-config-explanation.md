## 一、Master 节点配置详解

### 1.1 节点信息

**节点名称**：`sealos-staging-master-000`
- **角色**：Kubernetes Master 节点（控制平面）
- **用途**：集群管理、API Server、调度器、控制器等

### 1.2 计算资源配置

#### CPU：16 核
- **配置水平**：中高配置
- **适用场景**：
  - 管理多个 Worker 节点（通常 1 个 Master 可管理 100+ Worker）
  - 运行 etcd（需要较高 CPU 处理一致性协议）
  - 处理 API 请求和调度决策
- **性能评估**：✅ 充足，适合中小规模集群

#### 内存：32GB
- **配置水平**：中高配置
- **内存分配参考**：
  ```
  - Kubernetes 组件：~4-8GB
    ├─ kube-apiserver: ~1-2GB
    ├─ kube-controller-manager: ~500MB-1GB
    ├─ kube-scheduler: ~200-500MB
    └─ etcd: ~2-4GB（取决于数据量）
  - 系统预留：~2-4GB
  - 可用余量：~20-26GB（用于缓存和突发）
  ```
- **性能评估**：✅ 充足，可支持中等规模集群

### 1.3 硬盘配置

#### 容量：500GB × 1
- **配置水平**：中等配置
- **存储用途**：
  - etcd 数据存储（通常 < 10GB，但需要稳定）
  - 系统日志和审计日志
  - 容器镜像缓存（可选）
- **性能评估**：⚠️ 单盘配置，无冗余

#### IOPS：5800
- **存储类型判断**：SATA SSD（根据 IOPS 范围 5k-10k）
- **性能水平**：中等偏低（SATA SSD 的典型范围）
- **性能评估**：
  - ✅ 对于 Master 节点：**充足**
    - Master 节点主要是元数据操作，I/O 压力不大
    - etcd 主要是小文件随机读写，对 IOPS 敏感但需求不高
  - ⚠️ 如果 etcd 数据量大或写入频繁，可能需要更高 IOPS

**实际带宽估算**：
```
假设每次操作 4KB：
实际带宽 = 5800 IOPS × 4KB = 23.2 MB/s

假设每次操作 64KB：
实际带宽 = 5800 IOPS × 64KB = 371.2 MB/s（受限于 SSD 带宽上限）
```

## 二、Worker 节点配置详解

### 2.1 节点信息

**节点名称**：`sealos-staging-devbox-worker-001/002`
- **角色**：Kubernetes Worker 节点（工作节点）
- **用途**：运行 Devbox 容器（开发环境容器）
- **节点数量**：2 个 Worker 节点（高可用）

### 2.2 计算资源配置

#### CPU：8 核
- **配置水平**：中等配置
- **适用场景**：
  - 运行多个 Devbox 容器
  - 编译、构建等 CPU 密集型任务
- **性能评估**：
  - ✅ 对于开发环境：**充足**
  - ⚠️ 如果同时运行多个大型编译任务，可能成为瓶颈
  - 💡 建议：根据实际 Devbox 容器数量调整

#### 内存：16GB
- **配置水平**：中等配置
- **内存分配参考**：
  ```
  - 系统预留：~2GB
  - Kubernetes 组件（kubelet, kube-proxy）：~500MB-1GB
  - 容器运行时（containerd）：~500MB-1GB
  - 可用给容器：~13-14GB
  ```
- **性能评估**：
  - ✅ 对于开发环境：**基本够用**
  - ⚠️ 如果 Devbox 容器运行内存密集型应用（如大型 IDE、数据库），可能不足
  - 💡 建议：监控实际内存使用情况

### 2.3 硬盘配置

#### 容量：1TB × 2
- **配置水平**：中高配置
- **存储用途**：
  - 容器镜像存储
  - Devbox 容器数据（代码、构建产物）
  - 容器日志
- **配置优势**：
  - ✅ **双盘配置**：可做 RAID（提高性能或冗余）
  - ✅ **容量充足**：2TB 总容量，适合多个 Devbox 容器
- **性能评估**：✅ 充足

#### IOPS：5000（每盘）
- **存储类型判断**：SATA SSD（根据 IOPS 范围 5k-10k）
- **性能水平**：中等偏低（SATA SSD 的典型范围）
- **双盘配置的影响**：
  - 如果配置 RAID 0（条带化）：理论 IOPS = 5000 × 2 = **10000 IOPS**
  - 如果配置 RAID 1（镜像）：IOPS 不变，但提高可靠性
  - 如果独立使用：总 IOPS = 5000 × 2 = **10000 IOPS**（分别使用）

**实际带宽估算**：
```
单盘（每次操作 4KB）：
实际带宽 = 5000 IOPS × 4KB = 20 MB/s

双盘 RAID 0（每次操作 4KB）：
理论带宽 = 10000 IOPS × 4KB = 40 MB/s

单盘（每次操作 64KB）：
实际带宽 = 5000 IOPS × 64KB = 320 MB/s（受限于 SSD 带宽上限）
```

## 三、配置对比分析

### 3.1 Master vs Worker 对比

| 配置项 | Master | Worker | 说明 |
|--------|--------|--------|------|
| **CPU** | 16核 | 8核 | Master 需要处理更多管理任务 |
| **内存** | 32GB | 16GB | Master 需要运行更多系统组件 |
| **硬盘容量** | 500GB | 1TB × 2 | Worker 需要存储更多容器数据 |
| **硬盘数量** | 1块 | 2块 | Worker 需要更高可用性和性能 |
| **IOPS** | 5800 | 5000/盘 | Master 的 I/O 压力相对较小 |

### 3.2 配置合理性评估

#### ✅ 合理的配置
1. **Master 节点**：
   - CPU 和内存充足，适合管理多个 Worker
   - 单盘配置对 Master 节点足够（I/O 压力小）

2. **Worker 节点**：
   - 双盘配置提供更好的性能和可靠性
   - 容量充足，适合运行多个 Devbox 容器

#### ⚠️ 需要注意的点
1. **Worker 节点 IOPS**：
   - 5000 IOPS/盘 对于 Devbox 容器（编译、构建）可能偏低
   - 如果多个 Devbox 容器同时进行 I/O 密集型操作，可能成为瓶颈
   - 💡 **建议**：这正是需要配置 I/O 限制的原因（见磁盘 I/O 控制指南）

2. **Master 节点单盘**：
   - 无冗余，如果磁盘故障可能影响集群
   - 💡 **建议**：定期备份 etcd 数据

## 四、实际使用场景分析

### 4.1 Devbox 容器的 I/O 需求

根据文档中的参考值：
- **开发环境编译**：通常需要 1k-5k IOPS，带宽 50-200 MB/s

**当前 Worker 配置评估**：
- 单盘 5000 IOPS：✅ 可以支持 1-2 个 Devbox 容器同时编译
- 双盘配置：✅ 可以支持 2-4 个 Devbox 容器同时编译
- ⚠️ 如果超过这个数量，需要配置 I/O 限制避免相互影响

### 4.2 为什么需要 I/O 限制？

**场景示例**：
```
Worker 节点：5000 IOPS/盘
├─ Devbox 容器 A：运行 cargo build（需要 ~3000 IOPS）
├─ Devbox 容器 B：运行 npm install（需要 ~2000 IOPS）
└─ 业务容器 C：需要启动（需要 ~100 IOPS）

问题：容器 A 和 B 可能占满 I/O，导致容器 C 无法启动（Pleget 卡顿）
```

**解决方案**：
- 为 Devbox 容器配置 I/O 限制（如文档中的 BlockIO 配置）
- 限制每个 Devbox 容器最多使用 1000-2000 IOPS
- 保证业务容器有足够的 I/O 资源

## 五、配置优化建议

### 5.1 短期优化（软件层面）

1. **配置 I/O 限制**：
   - 为 Devbox 容器配置 BlockIO class
   - 限制每个 Devbox 容器的 IOPS 和带宽
   - 参考文档：`disk-io-control-guide.md`

2. **监控 I/O 使用**：
   - 使用 `iostat` 监控磁盘 I/O
   - 使用 `iotop` 监控进程 I/O
   - 设置告警阈值

### 5.2 长期优化（硬件层面）

1. **Worker 节点**：
   - 考虑升级到更高 IOPS 的 SSD（如 10k-20k IOPS）
   - 或使用 NVMe SSD（50k+ IOPS）

2. **Master 节点**：
   - 考虑添加第二块盘做 RAID 1（提高可靠性）

## 六、总结

### 配置特点
- ✅ **Master 节点**：计算资源充足，适合管理集群
- ✅ **Worker 节点**：双盘配置，容量充足
- ⚠️ **IOPS 水平**：中等偏低，需要合理配置 I/O 限制

### 关键建议
1. **立即行动**：为 Devbox 容器配置 I/O 限制，避免影响业务容器
2. **监控观察**：监控实际 I/O 使用情况，根据数据调整限制值
3. **长期规划**：如果 I/O 成为瓶颈，考虑升级硬件
